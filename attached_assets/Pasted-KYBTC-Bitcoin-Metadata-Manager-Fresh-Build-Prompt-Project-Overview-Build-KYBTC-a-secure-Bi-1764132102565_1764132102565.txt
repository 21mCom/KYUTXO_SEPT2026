KYBTC - Bitcoin Metadata Manager (Fresh Build Prompt)
Project Overview:
Build "KYBTC," a secure Bitcoin metadata manager that operates as an installable, offline-first Progressive Web App usable on both mobile and desktop. Choose the best technology stack and architecture to accomplish these goals reliably.

Core User Goals & Use Cases
Record Management - Capture and organize metadata for Bitcoin addresses and transaction IDs, with automatic detection of input type, manual editing, and bulk derivation of address lists from xpub/ypub/zpub keys

Search & Browse - Quickly search, filter, and browse saved records with faceted filtering across labels, tags, categories, counterparties, and custom fields

File Attachments - Attach photos, documents, and PDFs to records from device storage or via in-app camera capture

Custom Vocabularies - Manage user-defined lists (tags, categories, seed names) that populate multi-select inputs and persist across updates

Data Portability - Export/import the entire dataset with optional password-based encryption, plus opt-in encrypted cloud backup/restore (Google Drive, Dropbox)

Customizable Display - Configure which fields appear in forms, tables, and exports while preserving hidden field data

UI/UX Requirements
Responsive Layout - Dashboard-style main view with: global search bar, record table/grid with filters, and contextual edit panel. Works on desktop and touch devices.

Bitcoin Branding - Orange/charcoal color palette with KYBTC logo

File Handling - Drag/drop upload, multi-select pickers, thumbnail previews, progress indicators, and clear error messages

QR Scanning - Camera-based QR code reader that handles permissions gracefully and works in portrait/landscape

Bulk Xpub Wizard - Guided flow for xpub key entry, derivation path options, address preview, and batch save confirmation

Accessibility - Keyboard navigation, screen-reader labels, high-contrast support

Data Model
Record:

ID, input_string (address/txid), record_type
Label, notes, amount (BTC), date
Wallet metadata (seed name, wallet software, private key status)
Transaction metadata (counterparty, source)
Relationships: tags[], categories[], attachments[]
Timestamps (created, updated)
Attachment:

ID, record_id, filename, mime_type, size, binary data, created_at
Settings/Lists:

User-defined value lists for dropdowns
Field visibility and display preferences
Backup configuration
Technical Requirements
Offline-First - Full functionality without internet; local database persistence including attachments

PWA Installable - Manifest, icons, splash screens, standalone mode, proper caching strategy with user-facing update prompts

Privacy-Preserving - All data stays on device unless user initiates encrypted backup

Performance - Handle thousands of records and hundreds of attachments with pagination/virtualization

Reliable Validation - Accurate Bitcoin address and transaction ID validation; correct xpub/ypub/zpub address derivation

Error Handling - Clear error messages, logging, and diagnostic export capability

Quality Expectations
Clean, maintainable code architecture
Consistent component patterns
Proper separation of concerns
No runtime compilation requirements (avoid JSX without transpiler, etc.)
Robust caching strategy that doesn't block updates
Test coverage for critical paths (validation, derivation, encryption)
Choose the technology stack that best achieves these goals with reliability and maintainability as top priorities.
